# کلاینت با تنظیم آدرس داخل APK

[APK آمادهٔ ARM64 نسخهٔ 3.1.0](ClashRoyale-3.1.0-private-arm64.apk)

این APK برای اتصال به سرور این ریپازیتوری، پچ بومی اتصال و رمزنگاری دارد.
Frida، Gadget، اسکریپت یا کامپیوتر برای اجرای آن لازم نیست. نمایش صفحهٔ
تنظیمات و ورود این APK روی دستگاه Android هنوز تأیید نشده است؛ آزمون‌های
بومی و امضای APK در [گزارش ساخت](build-report.json) و
[گزارش اجرای بومی](native-verification.json) ثبت شده‌اند.

## نصب و تنظیم

1. `git pull origin main` را اجرا کن. APK در پوشهٔ `client` است.
2. قبل از حذف یا تعویض نسخهٔ نصب‌شده، نکتهٔ امضا و حساب در پایین را بخوان.
3. APK را نصب کن و **Clash Royale Private** را باز کن.
4. در صفحهٔ **Private server**، IP یا دامنه را وارد کن؛ مقدار پیش‌فرض
   `223.223.223.1` و پورت `9339` است. URL یا `http://` وارد نکن.
5. **Save and connect** را بزن. آدرس ذخیره می‌شود و بازی اجرا می‌شود.
6. برای تغییر آدرس، دوباره آیکون برنامه را باز کن و آدرس جدید را ذخیره کن.
   اتصال مجدد، پردازش قبلی خود بازی را می‌بندد و آن را با مقصد جدید باز می‌کند.

دامنه هنگام اتصال به IPv4 تبدیل می‌شود. دامنه باید رکورد A داشته باشد؛
IPv6 مستقیم در این نسخه پشتیبانی نمی‌شود. تغییر آدرس به ساخت دوبارهٔ APK
نیاز ندارد. داده‌های بازی یا حساب با تغییر آدرس پاک نمی‌شوند؛ حساب‌های
سرورهای مختلف لزوماً مشترک نیستند.

کلید عمومی ثابت داخل APK:

```text
8ddd4aa88e325e6cf7393740d2b9a9a952934477a44818bc0605d3b730cc5831
```

سرور باید با `TRANSPORT=nacl17` اجرا شود و همین کلید عمومی را چاپ کند.
کلید خصوصی سرور داخل APK نیست. پوشهٔ `.local` سرور، مخصوصاً
`server-key.json` و `accounts` را نگه دار. کلید جداگانه‌ای برای کلاینت لازم
نیست. آدرس دانلود محتوا همچنان از LoginOk سرور می‌آید؛ برای محتوا از HTTPS
معتبر استفاده کن.

## امضا و حفظ حساب

امضای اصلی APK در اختیار ما نیست. APK جدید امضای توسعهٔ مستقل دارد و با
همان نام بستهٔ `com.supercell.clashroyale` ساخته شده است. Android نصب آن
روی APK با امضای متفاوت را به‌صورت آپدیت نمی‌پذیرد.

**اگر حساب فعلی را می‌خواهی، پیش از حذف نسخهٔ قبلی از داده‌های خصوصی برنامه
بکاپ روت بگیر.** فقط نگه‌داشتن دیتابیس سرور کافی نیست؛ شناسه و توکن ورود
کلاینت هم در داده‌های برنامه هستند. با ابزار بکاپ روت خودت، حداقل
`shared_prefs` و `files` بستهٔ فوق را ذخیره کن و بعد از نصب با مالکیت و
برچسب SELinux صحیح برگردان. بکاپ را خصوصی و خارج از Git نگه دار. این
ابزار ساخت، هیچ دستگاهی را پاک، uninstall یا reset نمی‌کند. بدون بکاپ
قابل‌بازیابی، حذف برنامه می‌تواند دسترسی به حساب فعلی را از بین ببرد.

پس از این نصب اول، APKهای بعدی باید با همین امضای توسعه ساخته شوند تا
آپدیت بدون حذف داده نصب شود. فایل امضا و رمز آن فقط در `.local` سازنده
ذخیره شده‌اند و عمداً در Git نیستند. اثر انگشت عمومی گواهی:

```text
313f5133153360af5450005ad4bb8b66a4d89a3ceb4eb6b10d395e1eed1dd301
```

## روش ساخت و محدودهٔ آزمون

پچ فقط هفت فراخوانی بومی را به کد جدید تغییر می‌دهد: اتصال TCP، محاسبهٔ
کلید مشترک و nonceهای Login و پاسخ. Salsa17، احراز اصالت پیام‌ها، کدک‌ها
و منطق بازی از کتابخانهٔ اصلی استفاده می‌کنند. رمزگشایی رشته‌ها در startup
و شاخه‌های بررسی یکپارچگی اصلی حفظ شده‌اند؛ مقادیر مورد انتظار جدول‌های
متأثر از تغییر کد دوباره محاسبه می‌شوند. کتابخانه فقط برای ARM64 و همین
نسخهٔ پین‌شده است.

APK ارسالی کتابخانه‌ای با رشته‌های از قبل رمزگشایی‌شده داشت. سازنده از
`libg.so` اصلیِ جداگانهٔ ارسالی با هش `4dd79f…` استفاده می‌کند تا ورودی
رمزگشای startup درست باشد؛ کد اجرایی هر دو نسخهٔ ورودی یکسان است. DEX
اصلی، منابع و محتوای بازی تغییر نمی‌کنند. یک DEX کوچک برای Activity تنظیم
آدرس و یک segment فقط خواندنی/اجرایی به ELF اضافه می‌شود.

ساخت اختیاری روی Linux انجام می‌شود؛ Python، Java یا ابزار Android به
وابستگی‌های سرور Node.js اضافه نشده‌اند. جزئیات بازتولید در
[build.md](build.md) است. نصب و اجرای کامل روی گوشی، بررسی لابی و نبرد و
تغییر آدرس از UI همچنان به آزمون دستگاه نیاز دارد.
