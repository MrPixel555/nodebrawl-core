# کلاینت بدون Frida و بدون رابط تنظیمات

[APK آمادهٔ ARM64 نسخهٔ 3.1.0](ClashRoyale-3.1.0-private-arm64.apk)

با باز کردن برنامه، همان بازی اصلی مستقیماً اجرا می‌شود. صفحه، Activity،
دکمه یا منوی اضافه‌ای برای تنظیم آدرس وجود ندارد. پچ اتصال و کلید داخل
کتابخانه است و اجرای بازی به Frida نیاز ندارد.

## فایل تنظیمات

داخل APK فایل **`assets/configs.so`** قرار دارد. با وجود پسوند `.so`، این
فایل یک متن ساده است؛ آن را با ویرایشگر متن باز کن. فقط یک خط دارد:

```text
223.223.223.1:9339
```

برای دامنه، همان خط را مثلاً به این صورت عوض کن:

```text
game.example.com:9339
```

فرمت دقیق `host:port` است؛ URL، `http://`، JSON یا توضیح به فایل اضافه نکن.
دامنه باید رکورد A داشته باشد؛ IPv6 پشتیبانی نمی‌شود. پایان خط LF و CRLF
هر دو پذیرفته می‌شوند. فایل هم‌نام **`client/configs.so`** در Git، ورودی
ساخت APK است؛ فایل داخل APK همان `assets/configs.so` است.

در شروع برنامه، فایل تنظیمات بسته‌شده در APK به فضای خصوصی برنامه کپی
می‌شود؛ نسخهٔ جدید APK آدرس قبلی را جایگزین می‌کند. فایل گمشده یا نامعتبر
باعث اتصال به سرور دیگری نمی‌شود. آدرس دانلود محتوا همچنان از LoginOk
سرور دریافت می‌شود و باید HTTPS معتبر داشته باشد.

## تغییر آدرس و نصب

1. `git pull origin main` را اجرا کن؛ APK در پوشهٔ `client` است.
2. APK آماده روی `223.223.223.1:9339` تنظیم شده و بدون تنظیم اضافه باز می‌شود.
3. برای مقصد دیگر، `assets/configs.so` را در APK ویرایش و APK را دوباره امضا
   کن، سپس نسخهٔ جدید را نصب کن. برای این کار بازنویسی `libg.so` لازم نیست.

هر تغییر فایل داخل APK، امضای آن را باطل می‌کند؛ پس امضای دوباره لازم است.
برای نصب آپدیت بدون حذف داده، از همان کلید امضای APK نصب‌شده استفاده کن.
این اصلاح با **همان امضای توسعهٔ APK قبلی این ریپازیتوری** ساخته شده است؛
برای جایگزینی نسخهٔ قبلی ما، داده‌های بازی را پاک نکن.

ابزار خط فرمان اختیاری برای جایگزینی فایل و امضای مجدد، بدون کامپایل مجدد
Java یا کد بومی:

```sh
python tools/client/reconfigure.py \
  --apk client/ClashRoyale-3.1.0-private-arm64.apk \
  --config client/configs.so \
  --apksigner /path/apksigner.jar \
  --output .local/client-new-address.apk
```

این ابزار به Python، وابستگی‌های `requirements-build.txt` و Java نیاز دارد؛
وابستگی سرور همچنان فقط Node.js است. امضای محلی در `.local/client-signing.p12`
و فایل رمز کنار آن ذخیره/استفاده می‌شود. در یک checkout تازه، امضای جدید
تولید می‌شود و با APK منتشرشده یکسان نیست؛ برای آپدیت‌های خودت هویت امضای
خودت را نگه دار. این فایل‌های خصوصی در Git منتشر نمی‌شوند.

## کلید سرور و حساب

کلید عمومی سرور عوض نشده است:

```text
8ddd4aa88e325e6cf7393740d2b9a9a952934477a44818bc0605d3b730cc5831
```

سرور باید با `TRANSPORT=nacl17` همین کلید را چاپ کند. `.local/server-key.json`
و دیتابیس `.local/accounts` را نگه دار. تغییر `configs.so` کلید را تغییر
نمی‌دهد و کلید خصوصی سرور داخل APK نیست.

اگر از APK اصلی با امضای متفاوت به این کلاینت می‌آیی، Android آن را به‌صورت
آپدیت نمی‌پذیرد. پیش از حذف نسخهٔ اصلی، از داده‌های خصوصی بازی، حداقل
`shared_prefs` و `files`، با ابزار بکاپ روت خودت بکاپ قابل‌بازیابی بگیر.
فقط دیتابیس سرور کافی نیست؛ کلاینت هم شناسه و توکن ورود دارد. بکاپ را
خصوصی نگه دار و با مالکیت و SELinux صحیح برگردان. هیچ ابزار این ریپازیتوری
دادهٔ گوشی را پاک یا برنامه را uninstall نمی‌کند.

اثر انگشت گواهی امضای APKهای منتشرشدهٔ ما:

```text
313f5133153360af5450005ad4bb8b66a4d89a3ceb4eb6b10d395e1eed1dd301
```

## شواهد و محدوده

[گزارش ساخت و امضا](build-report.json)، [آزمون بومی](native-verification.json)
و [دستور ساخت](build.md) ثبت شده‌اند. DEX اصلی، Activity اصلی و فیلتر launcher،
منابع و محتوای بازی حفظ شده‌اند. فقط Application بدون UI برای کپی فایل
پیکربندی اضافه می‌شود. پچ بومی همان هفت call site را تغییر می‌دهد و
بررسی‌های یکپارچگی، Salsa17، احراز اصالت و کدک‌های اصلی را حفظ می‌کند.

اجرای APK اصلاح‌شده روی دستگاه Android هنوز تأیید نشده است؛ آزمون بومی و
تأیید امضا جای آزمون نصب و اجرای بازی روی گوشی را نمی‌گیرد.
