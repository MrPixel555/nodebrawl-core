# سرور پروتکل Clash Royale 3.1.0

این نسخه در nodebrawl-core، بر اساس کتابخانهٔ ARM64 و APK ارسالی ساخته شده است. **ورود، نمایش Home، دانلود محتوا و پروفایل روی گوشی تأیید شده‌اند.** موتور اصلی نبرد اکنون در Node.js با WebAssembly اجرا می‌شود: Training، صف نبرد، 1v1/2v2، ربات، اجرای کارت‌ها، نتیجه و بازگشت به Home پیاده‌سازی شده‌اند. کاربر باز شدن Training روی گوشی را تأیید کرد. ایراد رزرو اکسیر، پاسخ لغو مچ و ارسال نتیجهٔ نبرد اصلاح شده‌اند؛ Party شامل 2v2 و Double Elixir و ساخت و ذخیرهٔ کلن اضافه شده است. تغییرات جدید با آزمون بومی و TCP بررسی شده‌اند و نمایش آن‌ها روی گوشی هنوز نیاز به تأیید دارد. صندوق‌ها، بقیهٔ رویدادها و عملیات کامل کلن هنوز کامل نیستند. [جزئیات اصلاحات](docs/battle-device-fixes.md).

- کاتالوگ ۲۸۴ شناسه و ۱۷۴ کدک پیام؛ قالب‌ها با encoder/decoder اصلی کتابخانه بررسی شده‌اند. [وضعیت کدک و handler هر پیام](docs/packet-coverage.json) و [جدول کامل هر ۲۸۴ پیام و ۱۳۵ دستور](docs/packet-matrix.md).
- دریافت TCP تکه‌تکه، چند فریم در یک دریافت، محدودیت صف/اندازه، heartbeat و ذخیرهٔ اتمی حساب‌ها.
- انتقال اختیاری `nacl17`: Login رمز‌شده، LoginOk/LoginFailed رمز‌شده و کلید/nonce مستقل پیام‌های بعدی.
- اسکریپت Frida برای ثبت اتصال، تغییر آدرس و تنظیم اختیاری کلید عمومی سرور توسعه.
- مسیر رمزنگاری روی گوشی تأیید شد: سرور Login را باز کرد و گوشی LoginOk و Home را پذیرفت و صفحهٔ Home نمایش داده شد.
- Home مبتنی بر serializer اصلی اکنون هر ۹۵ کارت قابل‌جمع‌آوری و فعال در CSV این نسخه را باز می‌کند: هشت کارت در deck و ۸۷ کارت در مجموعه، پنج deck، Arena1 و منابع ذخیره‌شده. کارت‌های `NotInUse` اضافه نمی‌شوند؛ نمایش مجموعهٔ گسترش‌یافته روی گوشی هنوز آزموده نشده است.
- کاتالوگ ۱۳۵ دستور بومی و ۹۶ کدک بررسی‌شده (شامل اجرای کارت و شاخهٔ معمولی نتیجهٔ صندوق)؛ پیام EndClientTurn این نسخه `13597` است. انتخاب deck با `703`، تغییر کارت‌ها با `563` و جابه‌جایی دستی با `693`، انتخاب اولین نام با `948` و خرید بستهٔ سکه با `687` ذخیره می‌شوند؛ این تعداد کدک به معنای پیاده‌سازی منطق همهٔ دستورها نیست.
- بسته‌های سکه با قیمت اصلی ۶۰/۵۰۰/۴۵۰۰ جم، سقف طلا و کسر جم رایگان پشتیبانی می‌شوند. خرید و تغییر deck اتمی ذخیره می‌شوند؛ آزمون TCP موجودی ۱۱۰۰ سکه و ۴۰ جم را در اتصال دوباره حفظ کرد. پاداش رایگان مرحلهٔ صفر Pass با `836` اکنون ۵۰۰ سکه، سقف طلا و وضعیت دریافت ذخیره‌شده دارد؛ مراحل بعدی و پریمیوم هنوز کامل نیستند. خرید ۶۰ جم و ماندن موجودی بعد از اتصال دوباره را کاربر روی گوشی تأیید کرد. [جزئیات تغییرات](docs/unlocked-cards-and-shop.md).
- درخواست Player Profile با `12373`، پاسخ بومی `22757` از اطلاعات حساب می‌گیرد؛ نمایش پروفایل را کاربر تأیید کرد. آغاز خودکار انتخاب نام و Training Camp هنوز کامل نیست. [شواهد و محدودهٔ فعلی قابلیت‌ها](docs/player-state.md).
- هر ۱۲۰۰ فایل اصلی محتوا با هش تأییدشده داخل ریپازیتوری هستند؛ ۱۲۵ فایل غایب APK از CDN اصلی دریافت و بررسی شدند. آدرس اعلام‌شده به گوشی اکنون HTTPS است؛ سرویس HTTP محلی نیز روی 9338 فعال است.
- Training با `17967` و شاخهٔ معمولی `10953`، نبرد عادی با فرمان `527`، لغو صف با `13006`، ورودی نبرد با `16194` و بازگشت به Home اجرا می‌شوند. ۴۶ مربی مجاز و هندسهٔ ۵۳ منطقه از داده‌های اصلی بارگذاری شده‌اند؛ قوانین چالش‌های PvE جداگانه هنوز اجرا نمی‌شوند.
- پیام `28991` اکنون snapshot واقعی GameMode را با serializer اصلی می‌فرستد؛ `15263` بارگذاری را تأیید و `26980` فرمان‌ها و checksum را منتقل می‌کند. یک نبرد کامل بومی تا نتیجه، تطابق شبیه‌سازی کلاینت اصلی و اجرای مستقل هر ۹۵ کارت آزموده شده‌اند. [اجرا، شواهد و محدودیت‌ها](docs/native-battles.md).

ساخت کلن با `10453` هزینهٔ ۱۰۰۰ سکه را اتمی کم می‌کند و عضویت رهبر، نشان و نام را ذخیره می‌کند؛ تأیید با فرمان سرور `477` و اطلاعات کلن با `28165` ارسال می‌شود. جست‌وجوی `14783 → 24184` نام کلن‌های ذخیره‌شده را جست‌وجو می‌کند. عملیات کامل کلن و چت هنوز اجرا نشده‌اند. درخواست `16442` مربوط به دوستان است؛ رویدادهای 2v2 و Double Elixir از کاتالوگ Home می‌آیند. [محدودهٔ کلن](docs/alliance-wire.md).

درخواست آغاز لابی `11712` اکنون پاسخ خالی بومی `28299` می‌گیرد؛ این درخواست نام بازیکن را حمل نمی‌کند. مسیر نهایی تأیید نام دستور `948` می‌سازد. آخرین لاگ گوشی فقط `595` با ارجاع `[54,1]` داشت: این عمل، دریافت بوست ۲۴ساعتهٔ سرعت صندوق Arena1 است و اکنون با وضعیت دریافت و زمان باقی‌مانده در Home ذخیره می‌شود. اتصال دوباره زمان بوست را از نو شروع نمی‌کند. رویداد موفق آن `arena-boost-claimed` است؛ سایر پاداش‌های `595` هنوز کامل نیستند. [شواهد و محدودهٔ بوست](docs/arena-boost.md).

گیر کردن OK نام شناسایی و اصلاح شد: درخواست بررسی نام `16592` باید پاسخ `20821` بگیرد؛ پاسخ قبلی `25074` اشتباه بود و فرم منتظر می‌ماند. مسیر اصلی کتابخانه با پاسخ جدید به مرحلهٔ تأیید بعدی می‌رود. `name-check-result` نتیجهٔ بررسی را ثبت می‌کند؛ ذخیرهٔ نهایی با `948` و رویداد `starter-name-set` انجام می‌شود و در اتصال دوباره باقی می‌ماند. تأیید این اصلاح روی گوشی هنوز لازم است. اگر یک نوبت حاوی دستور پشتیبانی‌نشده باشد، کل نوبت رد می‌شود. [شواهد بومی و آزمون‌ها](docs/name-check.md).

علت برگشتن کارت‌ها، اجرا نشدن `693` بود. اکنون ترتیب هشت کارت و ۸۷ کارت خارج از deck ذخیره می‌شود؛ این ترتیب برای تفسیر شمارهٔ کارت در پیام‌های بعدی لازم است. دستور `869` هم بیت‌های بومی Home را ذخیره می‌کند. آزمون بومی، TCP، دریافت تکراری پاداش و راه‌اندازی دوباره بررسی شده‌اند؛ کاربر ماندن جابه‌جایی کارت‌ها و دریافت ۵۰۰ سکه را بعد از اتصال مجدد روی گوشی تأیید کرد. [جزئیات و محدودیت‌ها](docs/lobby-actions.md).

کرش‌های نبود فهرست رویدادها و ناهماهنگی سطح Home/Avatar اصلاح شده‌اند. در اجرای `network-v6` کاربر نمایش Home را تأیید کرد؛ سطح هر دو یک است. [شواهد گوشی](docs/device-lobby.json) و [جزئیات اصلاح](docs/lobby-crash.md).

وضعیت دیده‌شدن Pass با فرمان `762` ذخیره می‌شود. جدول هر پنج Pass شامل ۳۶۰ مسیر پاداش استخراج شده و کدک نتیجهٔ معمولی صندوق `235` و سه پیام تو‌در‌توی فرمان‌ها اضافه شده‌اند. این کدک‌ها هنوز به معنی کامل شدن تولید و دریافت محتوای صندوق نیستند. اجرای سرور فقط به Node.js نیاز دارد. [جزئیات، آزمون‌ها و موارد باقی‌مانده](docs/season-rewards.md).

## دریافت و اجرا

Node.js 18 یا بالاتر نیاز است. وابستگی موتور ARM64 با فایل آمادهٔ WebAssembly نصب می‌شود؛ اجرای سرور Python، کامپایلر یا پردازش جانبی نمی‌خواهد:

```bash
git pull origin main
npm ci
npm test
npm run lint
```

برای آزمون اتصال رمز‌شده، سرور را روی کامپیوتر یا سرور خود اجرا کنید:

```bash
TRANSPORT=nacl17 HOME_MODE=starter HOST=0.0.0.0 PORT=9339 npm start
```

معادل در Windows CMD:

```bat
set TRANSPORT=nacl17
set HOME_MODE=starter
set HOST=0.0.0.0
set PORT=9339
npm start
```

در اولین اجرا، کلید سرور در `.local/server-key.json` ساخته می‌شود. کلید خصوصی داخل Git نیست؛ آن فایل را بین اجراها نگه دارید. کنسول فقط **کلید عمومی** را نشان می‌دهد.

برای آزمون داخلی از ترمینال دیگر، کلید عمومی چاپ‌شده را جایگزین کنید:

```bash
EXPECT_HOME=starter SERVER_PUBLIC_KEY="PUBLIC_KEY_FROM_SERVER" node tools/smoke-client.js
```

بدون تنظیم `TRANSPORT`، سرور plaintext است؛ در حالت starter با `EXPECT_HOME=starter node tools/smoke-client.js` آزموده می‌شود. حالت plaintext به کلاینتی با تغییرات متناسب نیاز دارد.

بدون `HOME_MODE` یا `HOME_TEMPLATE_PATH`، Home غیرفعال است و پاسخ همان LoginFailed خواهد بود. **برای Home اولیه، `HOME_MODE=starter` را تنظیم کنید.** در این حالت سرور LoginOk و سپس OwnHomeData می‌فرستد. نمایش این Home روی گوشی کاربر تأیید شده؛ منطق کامل بازی هنوز پیاده‌سازی نشده است. [محدوده و شواهد Home اولیه](docs/starter-home.md).

برای آزمون داخلی سرور در حالت starter، از ترمینال دیگر اجرا کنید؛ کلید عمومی چاپ‌شده را جایگزین کنید:

```bat
set EXPECT_HOME=starter
set SERVER_PUBLIC_KEY=PUBLIC_KEY_FROM_SERVER
node tools/smoke-client.js
```

این آزمون LoginOk، Home با شناسهٔ حساب درست، پیام‌های پس از ورود، جست‌وجوی کلن با نتیجهٔ خالی و heartbeat رمز‌شده را بررسی می‌کند. آزمون قدیمی LoginFailed را با `HOME_MODE=disabled` روی سرور و `EXPECT_HOME=missing` روی کلاینت smoke اجرا کنید.

## دریافت محتوای بازی

آدرس پیش‌فرض اعلام‌شده به بازی اکنون **`https://game-assets.clashroyaleapp.com`** است و در دو بردار URL پیام LoginOk قرار می‌گیرد. هر ۱۲۵ فایل غایب از همین CDN با HTTPS دریافت و با fingerprint اصلی تطبیق داده شد؛ اکنون هر **۱۲۰۰ فایل، مجموعاً 176,402,252 بایت** داخل Git قرار دارند.

APK ارسالی `targetSdkVersion=28` دارد و اجازهٔ HTTP ساده یا تنظیم شبکهٔ سفارشی ندارد. بنابراین HTTP اعلام‌شده در نسخهٔ قبلی با سیاست پیش‌فرض این APK روی Android 9 به بعد سازگار نبود. مرورگر گوشی می‌تواند همان آدرس را باز کند، اما درخواست داخل برنامه پیش از پاسخ HTTP شکست بخورد و کد خطای صفر بفرستد. [شواهد manifest، مسیر Java و گزارش گوشی](docs/device-download-failure.json).

اگر قبلاً `CONTENT_URL` را در CMD تنظیم کرده‌ای، مقدار قبلی با `git pull` عوض نمی‌شود؛ آن را صریحاً جایگزین کن:

```bat
set CONTENT_URL=https://game-assets.clashroyaleapp.com
set TRACE_NETWORK=1
npm start
```

همان `npm start` سرویس HTTP محلی محتوا را روی پورت **9338** نگه می‌دارد؛ این سرویس برای آزمون یا پشت reverse proxy با HTTPS معتبر قابل استفاده است. برای میزبانی خودت، `CONTENT_URL` را به آدرس HTTPS معتبر آن proxy تغییر بده. پورت بازی همچنان **9339** است و کلید سرور/اسکریپت Frida عوض نشده‌اند. TLS یا سیاست شبکهٔ گوشی غیرفعال نمی‌شوند.

fingerprint محلی در مسیر `/fingerprint.json` و فایل‌ها در `/<fingerprint>/<asset-path>` سرو می‌شوند. سرور هر ۱۲۰۰ فایل را با SHA-1 اصلی بررسی می‌کند. برای بررسی و بازیابی فایل‌هایی که بعداً حذف شده‌اند:

```bat
node tools/fetch-content.js --base-url https://game-assets.clashroyaleapp.com
```

اکنون هر ۱۲۵ فایل از CDN اصلی دریافت شده‌اند و هیچ فایل غایبی باقی نمانده است؛ [گزارش بازیابی و هش‌ها](docs/content-restoration.json). فایل [inventory](content/inventory.json) سابقهٔ APK اولیه است. در Cloud از Node 24 با پراکسی محیط، دستور دریافت را با `node --use-env-proxy` اجرا کن. fingerprint و محتوای فایل‌ها تغییر داده نشده‌اند.

در لاگ جدید `content-http-response` وضعیت همهٔ درخواست‌های HTTP محلی، حتی مسیرهای ردشده، را بدون متن مسیر ناشناخته ثبت می‌کند. `content-file-served` دریافت فایل محلی را نشان می‌دهد. با `TRACE_NETWORK=1`، گزارش‌های شناخته‌شدهٔ دانلود کلاینت به شکل `client-content-event` با مرحله، مسیر شناخته‌شده و کد خطا ثبت می‌شوند؛ query، توکن و متن کامل متادیتا ثبت نمی‌شوند. با پیش‌فرض HTTPS، دریافت مستقیماً از CDN است و در HTTP محلی ثبت نمی‌شود. کاربر موفقیت دانلود روی گوشی را در اجرای network-v8 تأیید کرده است؛ مسیر نبرد و Training در [موتور بومی Node](docs/native-battles.md) پیاده‌سازی شده است؛ آزمون صفحهٔ نبرد روی گوشی هنوز لازم است. [جزئیات و آزمون‌ها](docs/content-training.md).

آزمون خودکار اجرای واقعی CLI، ورود رمز‌شده و دریافت HTTP، بدون تغییر حساب‌ها و کلید فعلی:

```bash
node tools/check-server.js
```

## آزمون دستگاه با Frida

اسکریپت آمادهٔ `client-dev.js` در ریشهٔ ریپازیتوری، برای سرور `223.223.223.1:9339` و کلید عمومی `8ddd4aa88e325e6cf7393740d2b9a9a952934477a44818bc0605d3b730cc5831` تنظیم شده است. اگر کنسول سرور همین کلید عمومی را نشان می‌دهد، پس از دریافت تغییرات مستقیماً اجرا کنید؛ دانلود فایل جداگانه از چت لازم نیست:

```bat
frida -U -f com.supercell.clashroyale -l client-dev.js -o frida-home.log
```

این فایل با `tools/make-client-trace.js` از سورس‌های ریپازیتوری ساخته شده و کلید خصوصی ندارد. برای آدرس یا کلید عمومی متفاوت، اسکریپت خودتان را طبق دستور زیر بسازید. فایل `.local/server-key.json` قبلی سرور را نگه دارید تا کلید عوض نشود.

در دستور زیر، `192.168.1.10` را با IPv4 قابل دسترس سرورتان و `PUBLIC_KEY_FROM_SERVER` را با کلید عمومی کنسول جایگزین کنید:

```bash
node tools/make-client-trace.js --host 192.168.1.10 --port 9339 --server-public-key "PUBLIC_KEY_FROM_SERVER" --trace-home 1 --output .local/client-jni.js
frida -U -f com.supercell.clashroyale -l .local/client-jni.js -o .local/frida-jni.log
```

**اسکریپت قدیمی را حذف/غیرفعال کنید و نسخهٔ تازه بسازید.** هم‌زمان دو اسکریپت را بارگذاری نکنید. گزارش کرش دستگاه نشان داد هوک‌های مستقیم قبلی در محدوده‌های checksum بازی قرار می‌گرفتند و بررسی یکپارچگی به مسیر کرش `libg+0x514b30` می‌رسید. نسخهٔ جدید هیچ هوک مستقیمی در کد `libg.so` نصب نمی‌کند؛ Stalker فقط نسخهٔ اجرایی موقت را ابزارگذاری می‌کند و checksumهای بازی غیرفعال نمی‌شوند.

نسخهٔ بعدی که کل GLThread را دنبال می‌کرد نیز روی Android 14 با Frida 17.15.4 در مسیر مفسر ART کرش کرد. نسخهٔ JNI بعد از آن روی گوشی باز ماند، ولی پیام Login به سرور رسید بدون اینکه رویداد تنظیم کلید ثبت شود. نسخهٔ `network-v2` دو صف `Messaging` را پوشش داد و ClientHello را مشاهده کرد، اما worker خواندن اتصال و مسیر ساخت Login داخل دریافت ServerHello را پوشش نمی‌داد. **نسخهٔ فعلی مانند `network-v3` علاوه بر اجرای بومی `GameApp.update()`، دو صف `Messaging` و worker خواندن اتصال متعلق به آن را پوشش می‌دهد.** آرگومان ورودی این workerها در `pthread_create` جایگزین می‌شود؛ کد کتابخانه و tuple اصلی thread تغییر نمی‌کنند. کتابخانهٔ ART و سایر کتابخانه‌ها از ردیابی کنار گذاشته شده‌اند. اسکریپت باید با `-f` و پیش از ساخت workerها بارگذاری شود.

برای `nacl17`، **کلید عمومی سرور** چاپ‌شده در کنسول را در `--server-public-key` قرار دهید؛ کلید جداگانه‌ای به نام «کلید کلاینت» لازم نیست. بازی جفت‌کلید موقت خودش را می‌سازد. کلید خصوصی `.local/server-key.json` را در اسکریپت یا لاگ قرار ندهید. در صورت عوض‌شدن کلید سرور، اسکریپت را با کلید عمومی جدید دوباره بسازید.

تنظیم کلید فقط در پردازش جاری انجام می‌شود. Stalker آرگومان کلید مشترک و nonce را در دو مسیر ساخت Login و مسیر بازکردن پاسخ تغییر می‌دهد؛ رمزنگاری پیام‌های جلسه به توابع خود بازی سپرده می‌شود. یک کپی از جدول JNI به `RegisterNatives` داده می‌شود تا اجرای `update()` از یک wrapper عبور کند؛ جدول اصلی تغییر نمی‌کند. پس از بازشدن نخستین پاسخ، تغییر آرگومان‌های رمزنگاری متوقف می‌شود. بدون گزینهٔ `--trace-home 1` ردیابی نیز همان‌جا تمام می‌شود؛ با آن گزینه ردیابی بومی تا پایان decode شدن Home یا بسته‌شدن اتصال باقی می‌ماند. اتصال تازه، workerهای بومی موجود را دوباره فعال می‌کند. ردیابی GLThread هنگام اجرای Java یا مفسر انجام نمی‌شود. این مرحله ممکن است کندتر اجرا شود. رمزنگاری و سپس نمایش Home با نسخهٔ `network-v6` روی گوشی تأیید شده‌اند.

اسکریپت معماری ARM64، ELF build ID و بایت‌های محل callها و ورودی workerها را کنترل می‌کند. در خروجی آمادهٔ جدید `diagnostics:"network-v8"` و `homeTrace:true`، سپس workerهای `events`، `send` و `socket` را بررسی کنید. `development-peer-open-result` با `result:0` بازشدن پاسخ رمز‌شده است. با فعال‌بودن starter، رویدادهای `native-home-decode-start` و `native-home-decode-complete` باید تعداد بایت مصرف‌شده، هشت کارت، پنج deck و `level:1,homeLevel:1` را گزارش کنند. برای Home اصلاح‌شده انتظار `eventsPresent:true,eventCount:0` و برای نام Player و شناسهٔ کوتاه، ۶۲۵ بایت داریم. این پایان decoder پیام است؛ پذیرش UI بعد از آن مرحله‌ای جداست. کلید خصوصی، توکن حساب، نام/شناسهٔ بازیکن و بدنهٔ Home ثبت نمی‌شوند. فایل خروجی `-o` متعلق به Frida است؛ logcat معمولی این رویدادهای JavaScript را ثبت نمی‌کند.

برای آزمون اتصال با **فقط هوک‌های libc**، دستور تولید را بدون `--server-public-key` و با نام خروجی تازه اجرا کنید. در این حالت نه Stalker فعال است و نه هوکی در `libg.so` نصب می‌شود؛ کلید بازی عوض نمی‌شود و ورود با `nacl17` سرور توسعه انتظار نمی‌رود. برای حفظ آدرس فعلی بازی، `--host` را هم حذف کنید. خروجی موجود بازنویسی نمی‌شود؛ برای اسکریپت تازه، نام خروجی تازه انتخاب کنید.

### Login ساخته می‌شود ولی به سرور نمی‌رسد

اگر Frida `development-peer-seal-result:0` دارد ولی سرور فقط `10100` دریافت کرده، ارسال Login هنوز ثابت نشده است. نسخهٔ آمادهٔ `network-v8`، رویدادهای `native-messaging-read-return`، `native-send-worker-dispatch` و `native-send-worker-return` را برای همین مرزها اضافه می‌کند. بازگشت null از parser برای ServerHello می‌تواند طبیعی باشد؛ dispatch هم به‌تنهایی ارسال موفق TCP نیست. [شواهد و محدودهٔ تشخیص](docs/login-send-diagnostics.md). برای آزمون مجدد نیازی به پاک‌کردن دادهٔ بازی، حساب‌ها یا کلید سرور نیست.

### اتصال برقرار است ولی بارگذاری جلو نمی‌رود

`game-connect-result` با `result:0` فقط برقراری TCP را تأیید می‌کند. ورود و نمایش Home در اجرای بعدی `network-v6` تأیید شدند. برای تشخیص توقف اتصال در اجراهای دیگر، در Windows CMD پیش از `npm start` اجرا کنید:

```bat
set TRACE_NETWORK=1
```

سرور اکنون `connection-open`، شمار بایت‌های دریافتی، `message-received` و `message-sent` را با یک `connectionId` ثبت می‌کند. ترتیب مورد انتظار شامل دریافت `10100`، ارسال `20100`، دریافت `10101` و در نبود Home ارسال `20103` است. اتصال ساکت بعد از ۳۰ ثانیه با `reason:"idle-timeout"` و شمار بایت/فریم بسته می‌شود. پیام `Home data missing` به‌تنهایی گزارشی از دریافت Login نیست.

اگر سرور `10101` را با `Ciphertext authentication failed` گزارش کند ولی Frida هیچ `development-peer-shared` یا `development-peer-seal` نداشته باشد، تنظیم کلید در مسیر رمزنگاری مشاهده نشده است؛ صرف ثبت `development-peer-enabled` موفقیت آن را ثابت نمی‌کند. در نسخهٔ فعلی، آماده‌بودن Login پیش از ServerHello نیز در آزمون بومی پوشش داده شده است: Login رمز‌شده توسط Node پذیرفته شد و پاسخ رمز‌شدهٔ Node توسط parser اصلی کتابخانه باز شد. این آزمون اجرای Android نیست. خط `Home data missing` علت شکست MAC نیست؛ پس از handshake موفق، نبود Home همچنان موجب LoginFailed می‌شود.

رویدادهای `native-client-hello-encode`، `native-messaging-state` و `native-login-build` مرحلهٔ بومی را مشخص می‌کنند. `native-frame-returned` و `native-frame-complete` پایان تابع و پایان ردیابی آن را جداگانه نشان می‌دهند. آزادسازی contextهای Stalker با تأخیر روی thread اسکریپت انجام می‌شود. ثبت سوکت، `send/recv`، `sendto/recvfrom` و `write/read` را پوشش می‌دهد؛ فراخوانی‌های تو‌در‌تو دوبار شمرده نمی‌شوند. شمار صفر این ابزار به‌تنهایی نبود ترافیک را ثابت نمی‌کند؛ گزارش واقعی دریافت سرور اولویت دارد. بدنهٔ پکت، توکن حساب و کلید خصوصی ثبت نمی‌شوند.

اسکریپت تازه را با نام خروجی تازه بسازید، بازی را از ابتدا با `-f` اجرا کنید و خروجی Frida و سرور را از شروع اتصال تا حداقل ۳۵ ثانیه ثبت کنید. این گزارش‌ها اتصال به listener اشتباه، اتصال بدون ClientHello و توقف پس از ServerHello را از هم قابل تشخیص می‌کنند.

| `BATTLE_ARENA` | `54000001`؛ منطقهٔ نبرد از Arena اصلی انتخاب می‌شود؛ Training منطقهٔ مربی را دارد |

اگر فقط `HOME_TEMPLATE_PATH` تنظیم شده باشد، حالت `template` انتخاب می‌شود. هم‌زمان آن مسیر و `HOME_MODE=starter` را تنظیم نکنید. حساب‌ها در `.local/accounts` باقی می‌مانند. موجودی، deck، نام و نتیجهٔ نبرد ذخیره می‌شوند؛ ارتقای کارت، تروفی و تولید صندوق هنوز کامل نیستند. نبردهای فعال در حافظه‌اند و پس از راه‌اندازی دوبارهٔ سرور ادامه پیدا نمی‌کنند.

در حالت starter، انتخاب یکی از پنج deck، چینش کارت‌ها و نام ذخیره می‌شوند و در ورود بعدی برمی‌گردند. دستهٔ حاوی دستور اجرا‌نشده به‌طور کامل بدون تغییر حساب گزارش می‌شود. [قالب‌ها، آزمون بومی و محدودیت‌های دستورها](docs/commands.md).

قالب Home شامل `librarySha256` مطابق پروفایل، `messageId: 21217`، `version`، `payloadHex`، `payloadSha256` و `accountIdOffsets` است. offsetها باید محل واقعی Long هشت‌بایتی شناسهٔ حساب باشند. بررسی checksum صحت فایل را می‌سنجد؛ سازگاری با بازی نیازمند آزمون جداگانه است.

برای توسعه، `createGameServer` از `server/core.js`، `AccountStore`، `homeProvider`، handlerهای شناسه‌محور در `Map` و `transportFactory` در دسترس‌اند. فیلدهای هنوز نام‌گذاری‌نشده با offset واقعی مثل `field_0x80` ثبت شده‌اند. داشتن کدک به معنای پیاده‌سازی منطق پیام نیست. پکت‌های بدون handler با وضعیت unsupported گزارش می‌شوند.

```bash
node tools/packets.js
node tools/packets.js --json
node tools/packets.js --commands
```

فایل‌های قدیمی `Protocol/` و `ByteStream/` حفظ شده‌اند؛ ورودی برنامه سرور جدید `server/` را اجرا می‌کند.

## شواهد و تحلیل

نسخه از AndroidManifest تأیید شده: `com.supercell.clashroyale`، نسخهٔ `3.1.0`، build `400`. نسخهٔ محتوا در fingerprint برابر `3.1945.13` است. کتابخانهٔ داخل APK دقیقاً برابر نسخهٔ رمزگشایی‌شدهٔ رشته‌های فایل اصلی است. ۱۴۹ جدول CSV باز شد، هش ۱۰۷۵ فایل موجود تطبیق داشت و ۱۲۵ فایل فهرست‌شده در APK نبودند.

```bash
python3 tools/apk-transfer.py join /path/client.apk.manifest.json --parts-directory /path/parts --output .local/client.apk
python3 tools/inspect-apk.py .local/client.apk --output .local/apk
python3 tools/apk_data.py .local/apk --output .local/game-data
python3 -m unittest discover -s test/python -v
```

خروجی `game-data.json` شامل ستون‌ها، نوع‌ها، نام رکوردها و هش جدول‌ها است. اکنون هر ۱۲۰۰ asset اصلی در `content/assets/` داخل Git هستند؛ خود APK و فایل خام کتابخانه در Git قرار نمی‌گیرند؛ موتور نبرد یک image فشرده از کد جابه‌جاشده، داده‌های پیوندخورده و LevelData دارد که با هش کتابخانهٔ اصلی بررسی می‌شود. `.gitattributes` از تبدیل پایان خط فایل‌های محتوا در Windows جلوگیری می‌کند تا هش آن‌ها تغییر نکند.

Home خالیِ استانداردشدهٔ ۴۱۶ بایتی با encoder و decoder اصلی رفت‌وبرگشت پایدار دارد. حالت تنظیم کلید توسعه نیز در مدل بومی، Login ساخته‌شده با توابع اصلی را در Node باز کرده و پاسخ رمز‌شدهٔ Node شامل LoginOk، همین Home خالی و KeepAlive را در parser اصلی خوانده است. Home خالی هنوز وضعیت معتبر قابل‌بازی نیست و به سرور پیش‌فرض وصل نشده است.

۷۳۲ آزمون Node و lint در اصلاحات نبرد، Party و ساخت کلن پاس شدند؛ ۹ آزمون ابزار APK نیز در مرحلهٔ قبلی پاس شده بودند. اجرای واقعی CLI در حالت‌های starter/nacl17، disabled/nacl17 و starter/plaintext همراه دریافت HTTP بررسی شده است. wrapper واقعی نیز با Frida 17.15.4 روی Linux x86-64 آزموده شد: دو بار ورود/خروج از تابع بومی، کپی جدول، تغییر آرگومان و پایان ردیابی پس از خروج بررسی شدند. این آزمون جای Android/ARM64 را نمی‌گیرد. آزمون‌های TCP هم Home مصنوعی و هم Home اولیهٔ بومی، پیام‌های پس از ورود، جست‌وجوی خالی کلن و انتخاب deck رمز‌شده را پوشش می‌دهند؛ آزمون‌های Unicorn اجرای Android نیستند. [گزارش توابع، شواهد و محدودیت‌ها](docs/compatibility.md) جزئیات و دستور بازتولید تحلیل بومی را ثبت می‌کند.
